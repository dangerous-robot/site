# Pipeline commands

The `dr` command contract: the five commands, their flags, what each writes, what can ask archive.org to capture a page, and the run rules every command follows. `dr --help` lists exactly `draft`, `recheck`, `review`, `findings` and `lint`; the repo-level `inv` tasks are in [AGENTS.md](/AGENTS.md) § Tooling: dr vs inv. Pipeline behaviour behind the commands is in [research-workflow.md](research-workflow.md) and [content-model.md](content-model.md); the flows are drawn in [research-flow.md](research-flow.md).

Global options (before the command): `--verbose`, `--model`, `--researcher-model`, `--analyst-model`, `--auditor-model`, `--ingestor-model`, `--tiebreaker-model` (env `DR_TIEBREAKER_MODEL`), `--restater-model` (env `DR_RESTATER_MODEL`; falls back to `--auditor-model`, then `--model`).

## Commands

| Command | Flags | Writes |
|---|---|---|
| `dr draft` | One mode flag, exactly one: `--entity`, `--subject`, `--criterion` with `--entity`, `--claim`, `--restates` with `--pick`, `--source`. Modifiers: `--dry-run`, `--force`, `--rerun analyst\|evaluator` (with `--claim` only), `--repo-root`, the research flags (`--max-sources`, `--candidate-pool-size`, `--skip-wayback/--wayback`, `--max-initial-queries`, `--llm-concurrency`) | A claim and its `.audit.yaml` sidecar as a draft, a run finding when the run was retried, tie-broken, abandoned or partial, and new source files |
| `dr recheck` | `--due`, `--dry-run` (with `--due`), `--claim REF`, `--sources ID...`, the research flags | A pending draft pair under `research/pending/` per claim; with `--sources`, only `archived_url` on the source files |
| `dr review` | none (walkthrough), `--format text\|json`, `--filter-entity`, `--claim REF` with `--approve` or `--archive`, `--correction`, `--reviewer`, `--notes`, `--pr-url` | A sign-off in the sidecar and the status flip; a promotion of a pending draft over the live claim. `--format` writes nothing |
| `dr findings` | none (open findings), `--all`, `--summary`, `--close ID --note TEXT`, `--replay [--finding ID]` | Closes a finding on request; with `--replay`, what `dr draft` or `dr recheck` would write, plus findings; deletes nothing |
| `dr lint` | `--entity`, `--format text\|json\|summary`, `--severity`, `--prune`, `--repo-root` | Nothing, except `--prune`, which deletes unreferenced source files |

### `dr draft` modes

A SENTENCE argument goes with `--entity` and `--subject` and is refused with any other mode. A wrong pairing is a usage error (exit 2) before any model call.

A company is not a claim target. An entity under `companies/`, however its ref is spelled (a `..` detour or other casing included), is a usage error (exit 2) in every mode that names a claim or an entity (`--entity`, `--criterion ... --entity`, `--claim`, `--claim --rerun`, `--restates`, `--claim --criterion`), before any model call: one text, naming products and subjects as the claim targets. For `--claim` and `--restates` the claim's `entity:` decides, since company and product claims share `research/claims/<slug>/`.

| Mode | Does |
|---|---|
| `--entity REF "<sentence>"` | Runs the loop on an ad hoc claim about an entity file (for example `products/chatgpt`) and writes it to `<entity-dir>/<slugified sentence>.md` with `status: draft` and no `criteria_slug`. There is no entity inference. `--force` overwrites an existing claim |
| `--criterion SLUG --entity REF` | Drafts the criterion's sentence for the entity. The text is rendered once with the entity name and stored as `statement`; the claim takes `criteria_slug` and the criterion's topics and is written to `<entity-dir>/<criteria_slug>.md`. The criterion's `grading_rule` reaches the Analyst and the Evaluator. An inactive criterion (`inactive: true` in `research/templates.yaml`) is a usage error (exit 2) for every entity type |
| `--subject SLUG "<sentence>"` | An ad hoc subject claim; writes `research/entities/subjects/<slug>.md` with the claim when the subject record is missing |
| `--claim REF --force` | Re-runs a draft claim's stored `statement` and writes back to the same path, keeping `criteria_slug`. Without `--force` or `--dry-run` it is a usage error. A published or archived claim is a usage error naming `dr recheck --claim REF` |
| `--claim REF --rerun analyst` | Re-runs the Analyst over the claim's stored sources (no search, no ingest, the loop's `rerun` entry only). A draft is rewritten in place: the sidecar's `audit` block becomes null before the claim is written (the Evaluator has not graded the new analysis), `pipeline_run.agents` becomes `["analyst"]`, the analyst's `models_used` entry is replaced, the auditor's and tie-breaker's are dropped and the others kept, and `research`, `sub_questions`, `sources_consulted` (with `acquisition`, `archive`, `quotes`, `recheck`) and `restatement` carry forward. A published or archived claim gets a pending draft and the live files are untouched |
| `--claim REF --rerun evaluator` | Re-runs the Evaluator (and the tie-breaker when the two verdicts differ) over the claim's stored sources; it grades `statement`. A draft's sidecar is rewritten in place keeping the other agents' `models_used`, `level_clamp`, `research`, `sub_questions` and each source's `acquisition` and `archive`. When the tie-breaker settles on a verdict other than the claim's, the claim takes the pipeline verdict and confidence too. A published or archived claim gets a pending draft |
| `--claim REF --criterion SLUG` | Attaches a new criterion to an ad hoc draft: appends the entry to `research/templates.yaml` and sets `criteria_slug`. No model call, no file moved. Refused when the slug exists, the claim already has `criteria_slug`, or the claim is not a draft. A claim needs `criteria_slug` before `dr review --approve` publishes it |
| `--restates REF --pick N` | Runs candidate N of the original claim's sidecar `restatement` block as a new claim (second run, second sign-off) and writes `restates: REF` in the new sidecar. There is no SENTENCE: the text and the entity come from the sidecar. Refused before any model call when the block or candidate N is missing, and when the candidate's text would give the original's own file name. The pick is recorded on the original's sidecar only after the new claim is written, and not at all when the original is published or archived (the live sidecar is never opened for writing) |
| `--source URL` | Ingests one page (an editorial page, for example) into `research/sources/<year>/<slug>.md` and writes nothing else: no claim, no sidecar, no finding, no loop run. The URL must start with `http://` or `https://`. `--force` overwrites the source file of the same URL |

`--dry-run` runs the same work, prints the result and writes nothing (not even a finding), and never asks archive.org to capture a page. `--rerun` has no `--force`: it writes unless `--dry-run`.

Usage errors (exit 2, before any model call) besides a wrong mode pairing: `--rerun` with a SENTENCE, with `--criterion`, with `--force` or with `--max-sources`, `--candidate-pool-size`, `--max-initial-queries` or `--llm-concurrency` (a rerun searches nothing); `--source` with a SENTENCE, with `--criterion`, with one of those four flags, or with both `--force` and `--dry-run`; `--claim` with `--criterion` and either `--force` or `--dry-run`. A `--claim` rerun of a claim whose `status` is not `draft`, `published` or `archived` exits 1 before any model call, with or without `--dry-run`.

A `--rerun` that fails or is abandoned writes only its finding (with the claim's ref) and exits 1. When a published or archived claim already has a pending pair, `--rerun` reruns from the pending claim, the newest draft of that claim. A batch over many claims is a shell loop over refs.

### Pending drafts

A published or archived claim is never rewritten in place. `dr recheck --claim`, `dr recheck --due` and `dr draft --claim REF --rerun analyst|evaluator` write the result as a pending draft: claim plus sidecar at `research/pending/<entity-dir>/<claim-slug>.md` and `.audit.yaml`, with `status: draft`, `human_review` reset and no `verdict_override`. Only `dr review --approve` (promotion) touches the live files: it carries the operator fields edited on the live claim since the pending draft was seeded (`tags` and `corrections`, merged with the pending draft's when both changed; and under the keep rules `takeaway`, `seo_title` and `cap_rationale` while the pending draft left them as seeded) into the promoted claim, keeping a review edit on the pending draft (it wins over a live edit of the same text field), writes the refresh snapshot and resets the sign-off. See [content-model.md](content-model.md) for the pending-draft write order.

### Archive.org captures

Archive.org captures (Save Page Now): `dr draft`, `dr draft --source` (without `--dry-run`), `dr recheck` and `dr findings --replay` (unless the replayed finding's config skips the lookup) ask archive.org to capture a page that has no snapshot yet (`--skip-wayback` turns the lookup off where offered). `dr draft --dry-run` and `dr draft --source --dry-run` check for an existing snapshot only, and the dry run of `dr recheck` (the due list) makes no archive.org call at all. A capture counts only when archive.org returns a dated snapshot link that replays with HTTP 200 for the same page.

### `dr findings`

`dr findings` lists open findings (abandoned, recovered, tie-broken and partial runs) and half-claims, newest first; `--all` includes closed ones, `--summary` counts open findings by step, rule and outcome, and `--close ID --note TEXT` records a hand triage. `--replay [--finding ID]` re-runs each open abandoned or half-claim finding's recorded claim spec and config through the loop, under one LLM limit, printing one summary line per finding (a `dr recheck` finding also prints the recheck's own `<ref>: ...` line above it). A success closes the finding (`closed.by: replay`); a failure records a new finding with `replays:` naming the old one and leaves the old one open. A chain of such findings is replayed once, through its newest finding, even when `--finding` names an older one. A `dr draft` finding writes a draft and a `dr recheck` finding writes a pending draft. A `dr draft` finding is not replayed when `dr draft` would now refuse it, for example when its entity is a company or its criterion is gone or inactive. Recovered, split and partial findings are skipped, and so are the findings of `dr draft --claim REF --rerun analyst|evaluator` (recorded as `command: dr draft --rerun <agent>`): a replay is a full run, which would force-write over the draft, so the skip line names the `--rerun` command to run again. Each replayed finding costs one full run. It deletes nothing.

### `dr lint`

`dr lint` runs static content checks (no model call, no network) and exits 1 on errors. `--format text` lists every issue by file, `json` prints an array of issues, `summary` prints counts by check; CI uses `json` (errors only), and `inv audit` uses `summary`. `--prune` takes no `--entity` (a usage error: it reads every claim to find unreferenced sources); it runs the same checks and, when they report no error, deletes the files of every `unreferenced-source` issue (with an error it deletes nothing and exits 1, since a claim that does not parse cites nothing the checks can see) and the year directories they empty; a source cited only by a pending draft under `research/pending/` counts as referenced. A pruned file cannot be recovered except from git. The pre-commit hook is `scripts/git-hooks/pre-commit` (see [runbook](../runbook.md) § Linting and the pre-commit hook).

## Run rules

No run asks a person anything. Every situation below has a rule. The error policy in `pipeline/loop/policy.py` maps each failure to one of them.

| Situation | Rule |
|---|---|
| Startup | The provider key for each configured model is checked, and the Brave key only when `search_backend` is `brave`. An entity ref that names no file is a usage error before any model call |
| Pipeline flaw mid-run: no queries, no search results, the scorer drops everything, fewer than 4 usable sources, every candidate `invalid_source` or `fetch_failed`, Analyst or Evaluator output invalid after PydanticAI's own retries | The failed step and the steps after it rerun once, keeping earlier outputs in memory; then the run is abandoned: nothing is written and a finding is recorded (claim spec, config, step, rule, error, date, run id). A retry that succeeds still records a finding with outcome `recovered`, because a rerun can differ by model variance |
| Infrastructure failure: timeout, `http_error`, rate limit, null body, archive.org 429, both search backends failing | Retried twice with backoff (45 s, then 90 s); then the run is abandoned with a finding. Fatal configuration errors (`api_key_missing`, `all_blocked`, a bad ref) abandon at once with a finding |
| Half-claim | The writer runs only after the loop succeeds, so a failed run leaves no claim, no sidecar and no fresh source file. The only half-claim left is a crash between the claim write and the sidecar write; `dr findings` lists claims without a sidecar: a draft is replaced by `dr draft --claim REF --force`, and a published or archived claim is rerun into a pending draft by `dr recheck --claim REF`. Nothing is deleted automatically, so automatic cleanup can never reach a published claim |
| Failed rerun of a claim that is published or archived | Nothing is written; the live claim and its sidecar stay untouched; a finding is recorded |
| Any write aimed at a published or archived claim | One rule for every command: `dr recheck --claim`, `dr recheck --due` and `dr draft --claim REF --rerun analyst\|evaluator` write a pending draft at the pending location and never touch the live claim file or sidecar. `dr draft --claim REF --force` on such a claim is a usage error pointing at `dr recheck --claim REF`. Only `dr review --approve` (promotion) touches the live files |
| Analyst and Evaluator disagree | The trigger is "verdicts differ" only. A tie-breaker runs blind (no analyst or Evaluator verdict in its prompt) on its own model slot (`--tiebreaker-model` or `DR_TIEBREAKER_MODEL`, falling back to `--model`). A tie-breaker verdict matching either side becomes the pipeline verdict; a three-way split takes the weakest side by the tie-breaker ordering, with that side's confidence. The sidecar records all three sides, `pipeline_verdict` and `rule_applied`; the run continues |
| Evaluator lists two or more evidence gaps but agrees on the verdict | No tie-breaker; the gaps appear in the review packet |
| Content judgment (restatement) | The restater runs inside the loop when the pipeline verdict is `unverified`, `mixed` or `not-applicable`, or when the tie-breaker ran. Ranked candidates, each with the verdict the pool would give it, are recorded in the sidecar; the original is kept and drafted; the pick is made at `dr review` and recorded as `restatement.picked: <n>`; `dr draft --restates <claim-ref> --pick <n>` then runs candidate `<n>` as a new claim with `restates:` set |
| Restater fails (invalid output after retries, or transport exhausted) after a valid pipeline verdict | The claim is written without a `restatement` block; a finding is recorded with `step: restate`, `outcome: partial`; `dr review` prints "restatement unavailable (finding <run-id>)" in place of the candidates. The paid Analyst, Evaluator and tie-breaker result is never thrown away for a restater failure |
| Tie-breaker fails (invalid output after retries, or transport exhausted) | A flaw: the run is abandoned with a finding (`step: tiebreak`, `outcome: abandoned`), because no `pipeline_verdict` exists without it; nothing is written |
| Publish | Only `dr review` at a tty, by a person, flips a claim to `published`. No bulk or unreviewed path exists |
| Recheck | A claim is due when `next_recheck_due` has passed or, without one, when `as_of` plus `recheck_cadence_days` (default 60) has passed. `dr recheck --due` processes every due claim and `dr recheck --due --dry-run` lists them with their due dates and calls no model. Each claim's failure becomes a finding and the batch continues. A recheck result lands as a pending draft beside the live claim; promotion at `dr review` writes the refresh snapshot and requires a correction when the verdict changed. Every pending recheck, changed or not, is promoted by a person; the packet header says "verdict unchanged, N of N quotes still found, M sources re-fetched" or "verdict changed: <old> to <new>" |
| Recheck that changes a verdict | The changed verdict never replaces the live claim on its own; it stays pending until a person promotes it at a tty with a correction |
| Cached sources on recheck | A cached source older than the cadence is fetched again, its quotes and archive link re-checked, and the outcome recorded per source in the pending sidecar; the shared source file is never rewritten by a recheck |
| Archive.org | `dr draft --dry-run` never saves; `dr draft` and `dr recheck` save only when no good capture exists and never after a 429 |
| Batch runs | Claims run one after another under one LLM limit; one summary line per claim (ran, recovered, abandoned, verdict changed); exit 0 unless the command itself failed to start |
| Claim status | A claim's status is `draft`, `published` or `archived`. Any other value is a `dr lint` error (`invalid-claim-status`) and fails the site build. A run that produces no verdict writes no placeholder claim |
| Tracked research output | `research/findings/` and `research/pending/` are tracked, not ignored: findings are the durable record a person triages, and a scheduled run must commit its pending drafts. The site's claims loader reads `research/claims/` only, so neither directory reaches the site. `dr lint` ignores `research/findings/` and lints a pending draft as a draft, counting its `sources:` as citations |
